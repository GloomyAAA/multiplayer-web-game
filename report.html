2. Game Application Architecture

The puzzle game is a real-time multiplayer application built with Node.js, Express, and Socket.io. The game implements a turn-based block placement puzzle on a 4x4 grid where players earn points by creating lines of three or more blocks sharing the same shape or color. The game features four shapes (circle, square, triangle, star) and four pastel colors (pink, purple, green, blue).

2.1 Server-Side Implementation

The server maintains the complete game state including:

  • The 4x4 grid with placed blocks
  • A pool of 16 unique blocks (4 shapes × 4 colors)
  • Active player list with turn order
  • Player scores
  • 60-second turn timer for each player

The GameState class encapsulates all game logic including block placement, line detection (horizontal, vertical, and all diagonals), score calculation, and jackpot handling when the grid is completely filled.

2.2 Client-Server Communication with Socket.io

Socket.io enables real-time, bidirectional communication between the server and all connected clients. The following events are implemented:

  • register_player - Client sends player name; server adds player to the game and places them at the end of the turn order.
  • get_current_block - Client requests the current block for their turn; server randomly selects a block from the pool.
  • place_block - Client sends grid coordinates and the block; server validates the move and updates game state.
  • game_update - Server broadcasts to all clients after each move, containing updated grid, scores, and current player.
  • players_update - Server broadcasts when players join or leave.
  • turn_changed - Server notifies all clients when the turn advances.
  • turn_timeout - Server notifies when a player fails to act within 60 seconds.

2.3 Game Logic Implementation

The core game mechanics work as follows:

  1. Turn Management: Players take turns in a cyclic order. When a player joins, they are appended to the end of the list.
  2. Block Placement: On a player's turn, they receive a random block from the pool and must place it in an empty cell.
  3. Line Detection: After placement, the system checks all horizontal, vertical, and diagonal lines (including all possible 3+ length diagonals) for consecutive blocks sharing the same shape OR same color. Groups of 3+ blocks are cleared.
  4. Scoring: Each cleared block awards 1 point. Filling the entire grid awards a 16-point jackpot and clears all blocks back to the pool.
  5. Player Departure: When a player disconnects or times out, they are removed and the turn order adjusts automatically.

3. Reflection

3.1 Challenges Faced

Line Detection Algorithm: The most complex part was implementing the line detection system that identifies consecutive blocks of 3+ with matching shape OR color in all four directions (horizontal, vertical, and all diagonals). I extended the diagonal detection to cover all possible 3+ length diagonals, not just the two main diagonals, to ensure fair gameplay.

Real-Time State Synchronization: Ensuring all clients maintain the same game state required careful design of Socket.io events. Using server-authoritative architecture where the server validates all moves and broadcasts updates proved effective.

UI Stability: A challenge was preventing the game board from moving when notification messages appeared and disappeared. I solved this by moving the message display to the sidebar and using fixed-height containers with opacity transitions instead of display:none.

Shape Display Consistency: Initially, CSS clip-path shapes would sometimes display incorrectly. I switched to using Font Awesome icons for shapes (circle, square, triangle, star) which provided consistent, reliable rendering across all browsers.

3.2 Lessons Learned

  • Socket.io Event Design: Learned the importance of designing clear event contracts with proper callback functions for acknowledgment.
  • State Management: Keeping all game state on the server simplifies client logic and prevents cheating.
  • CSS Grid Layout: Gained proficiency in using CSS Grid for both the game board layout and responsive page designs.
  • Error Handling: Implementing proper error callbacks improves user experience by providing immediate feedback.
  • Pastel Color Scheme: Learned to implement custom color schemes (pink, purple, green, blue) for better visual appeal.
  • HTML Validation: Used the W3C Markup Validation Service to check my HTML code. It identified a heading level issue (h1 directly followed by h3). After fixing this by changing h3 tags to h2, all pages passed validation with no errors or warnings.
